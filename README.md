# Small-Scale Waste Sorter

Training uses CUDA when available and otherwise falls back to the CPU. ONNX
inference runs on the CPU. The model labels and their order are defined in
`config.yaml` and mirrored in `models/labels.json`.

## Setup

Create and activate a virtual environment, then install PyTorch and torchvision
using the command generated by the [PyTorch Get Started selector](https://pytorch.org/get-started/locally/)
for your CUDA version (or choose its CPU option). Install the remaining
dependencies afterward:

Windows (PowerShell):

```powershell
py -3.11 -m venv .venv
.venv\Scripts\Activate.ps1
# First install torch and torchvision with the command from the selector above.
pip install -r requirements.txt
```

macOS (zsh or bash):

```bash
python3.11 -m venv .venv
source .venv/bin/activate
# First install torch and torchvision with the command from the selector above.
pip install -r requirements.txt
```

Linux (bash):

```bash
python3.11 -m venv .venv
source .venv/bin/activate
# First install torch and torchvision with the command from the selector above.
pip install -r requirements.txt
```

Run the `pip install -r requirements.txt` line after the PyTorch command: the
requirements file does not install PyTorch, so it will not replace your selected
build. On Linux you may also
need the `python3.11-venv` package and, for the camera, membership of the `video`
group. On macOS the first camera access asks for permission for your terminal.

## Project layout

```text
waste-sorter/
├── data/
│   ├── raw/                 # downloaded public datasets, untouched
│   ├── own/                  # your photos, grouped by source class
│   ├── processed/            # train/val/test split, grouped by output class
│   ├── trashnet/             # supplied TrashNet archive
│   └── combined/             # supplied parquet shards
├── models/                   # checkpoints, ONNX model and labels.json
├── src/                      # Python modules
├── web/                      # dashboard assets
├── firmware/                 # controller firmware
└── config.yaml               # paths, labels, class-map path, thresholds and ports
```

## Data class mapping

Source folder names are mapped to the six model outputs by `data/class_map.yaml`:
paper/cardboard maps to paper, glass to glass, plastic(s) to plastic, metal(s) to
metal, and biological, e-waste, and trash categories to other. Unrecognized source
folders are skipped with a warning. The supplied datasets do not contain an
empty-tray class; capture those images under `data/own/empty/` before training.

## How to run: prepare data

Put public datasets under `data/raw/<dataset_name>/<source_label>/` and your own
photos under `data/own/<class>/<itemid>_<n>.jpg`. Then run:

```bash
python -m src.prepare_data
```

On each run the script also, when the matching paths in `config.yaml` exist:

- unpacks `data/trashnet/dataset-resized.zip` into `data/raw/trashnet/<label>/`
  (skipped if that folder already has images)
- materializes `data/combined/data/*.parquet` into `data/raw/combined/<label>/`
  (skipped if that folder already has images; needs `pyarrow`)

Images are copied (never moved) into `data/processed/{train,val,test}/<class>/`,
with a 70/15/15 split read from `config.yaml`. Own photos are split by `itemid`,
so every picture of one physical item stays in a single split. Corrupt images and
exact byte duplicates are dropped, and the longest side of each image is resized
to at most 256 px and saved as JPEG. The script prints a per-class, per-split
count table and warns for any class with fewer than 150 training images.

Fetch the public TrashBusters dataset from Hugging Face instead of the local
parquet (needs `pip install datasets`):

```bash
python -m src.prepare_data --download-hf
```

Add `--clear` to replace the existing processed directory.

## How to run: write labels

```bash
python -m src.common --write-labels
```

## How to run: train the classifier

Training reads `data/processed/manifest.csv`, uses equal default source weights,
and saves `models/best.pt` and `models/training_log.csv`. `auto` selects CUDA when
available; the exported ONNX model remains usable on a CPU.

```bash
python -m src.train
python -m src.train --max-batches 5 --stage1-epochs 1 --stage2-epochs 1
```

## How to run: shared config (src/common.py)

`src/common.py` is the only reader and writer of `config.yaml`. It exposes
`load_config() -> dict`, `save_config(cfg) -> None`, `get_classes() -> list[str]`
and `set_seed(seed) -> None`.

```bash
python -m src.common                 # print the ordered class labels
python -m src.common --write-labels  # regenerate models/labels.json
```

Edit `config.yaml` for classes, thresholds, camera and server ports, then let
every other module read those values through these helpers instead of hard-coding
them.

## How to run: web server (src/server.py)

The server runs the live camera loop in a background thread and serves the
dashboard at the host and port configured in `config.yaml` under `server:`.

```bash
# Webcam (default device from config.yaml camera_index)
python -m src.server

# Recorded video file
python -m src.server --video data/test_video.mp4
```

The LAN URL is printed at startup.  Open it in any browser on the same network.

Endpoints:

| Method | Path | Description |
|--------|------|-------------|
| `GET` | `/` | Serves `web/index.html` |
| `GET` | `/stream` | Motion-JPEG camera stream with OSD overlays |
| `GET` | `/api/status` | State name, guidance message, last event, FPS and paused flag |
| `GET` | `/api/stats` | Per-class counts, uncertain decisions and false triggers |
| `GET` | `/api/log?n=50` | Last *n* events with thumbnail URLs |
| `POST` | `/api/settings` | Update `confidence_threshold` (0.30–0.99) and/or `paused` (bool) |
| `POST` | `/api/continue` | Recapture the current tray as empty and continue |
| `POST` | `/api/restart` | Reset transient sorter state and clear pause/error flags |

Settings changes take effect immediately and are saved to `config.yaml`.
If the camera is unavailable the stream shows a grey placeholder and an error
banner appears in the UI without crashing the server.

## Live tray controls and recovery

The empty-tray reference slowly adapts to calm lighting changes while the sorter
is IDLE. `reference_alpha` controls that EMA rate (default `0.02`). After a
decision, the sorter leaves `WAIT_CLEAR` when the tray is clear for
`stable_frames` at `release_threshold` (default `1.5 × empty_diff_threshold`),
or after repeated confident empty-class checks. `clear_timeout_s` (default
`20.0`) controls when the UI asks you to remove the item and press Continue.

Continue captures the current tray as the empty reference and returns to IDLE.
Restart also clears transient state and pause/error flags while keeping counts
and the event log. The dashboard has Continue and Restart buttons; the OpenCV
window uses `c` and `x` respectively. `r` still recaptures the reference, `p`
pauses/resumes and `q` quits. False triggers are counted separately from sort
events so `empty_diff_threshold` can be tuned.
